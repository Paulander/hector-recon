# Fresh owner-local acquisition comparison

Declared 2026-09-15 before cohort play. The user explicitly requested fresh
networks, no new split-timing knobs, and no external macro/network guidance.
The previous pilot's phrase "stronger learned starting policies" meant already
learned behavior; this study instead answers the user's fresh-start request.
It does not complete the separate strong-skill retention benchmark.

## Fixed experiment

Use previously unused study seeds 12, 13, 14. Each seed has two independent
fresh learners: random/current and residual/current. Both start at completed=0,
one root owner, one zero-valued bias, no learned scoring features, zero evidence,
and no known action bindings. No prefix checkpoint or training is imported.
The constructor reuses the empty ancestor's data structures, with the declared
typed terminal schema only. One generic unbound request site satisfies the
formal SCRIPT-child rule without reading the environment. The formal catalog
discovers actual action bindings.
The matched exploration RNG is active from the first action; the ancestor's
unused 128-action flat-prefix RNG switch is bypassed throughout.

Retain the previous study's 24-candidate grammar/pool, 25% random eligibility
path, four-observation support requirement, compatibility gate, current birth
schedule, ordinary credit/consolidation/pruning, 64-local-visit development clock,
and limits: four owners, 64 parameters, 256 definitions, 2,048 physical nodes,
depth four. Learning rate .3, exploration .25, all other DevelopmentConfig
defaults, max_conditions=8 as in the original prefix configuration (owner
parameter limits govern owned growth). Splitting is available from the first
local development opportunity. No handpicked or pre-grown condition is added.
Paired arms share initial pools, route candidates, sampling and RNG states.
Only the birth selection mode differs; later actions and local histories may
diverge. No extra-after-split births or delayed/coarse splitting.

Each learner receives the same fixed 1,920-action schedule: 640 A, 640 mostly B,
640 mostly A, generated by the previous fivefold schedule function with its new
seed. These are externally defined task distributions for the measurement, not
phase labels or graph-dependent curricula supplied to the learner. Evaluate all
16 rows on disposable clones initially and every 64 actions. Neither results nor
graph diagnostics feed back into training or choose the stopping point.

Totals: 11,520 training actions; 2,976 scheduled evaluations including the six
initial evaluations; 2,976 frozen reproduction actions; 180 blocks and 186
checkpoints. No extra play, seed replacement, score-based stopping or automatic
retry. One CPU, numerical libraries one thread, 2 GiB address space, 64 MiB per
file, 3,600-second worker deadline, independent 3,630-second timeout and five-
second kill grace. Preserve and report incomplete evidence if limits are hit.

## Boundary and interpretation

Only selected-binding formal terminal confirmations and the matching actual
scalar residual update the active owner's statistics. Split nomination, birth
selection and pruning use that owner's internal history under the existing
generic supplied rules. No network-wide reward analysis, task rule, desired
route, fitted weights, alternate-action outcome or evaluation score is exposed.
Global resource limits constrain allocation; they do not choose useful routes.
The supplied Python developmental law is not itself learned by the graph.

Starting ownership at birth differs from the previous 640-trained-action
conversion. This is a from-scratch acquisition comparison, not an otherwise
identical replication of that warm-start pilot. The initial root has no learned
expressive scoring structure; its development must be earned by actual exposure.
The fixed candidate pool is still bounded experimental machinery internal to the
learner, not a claim of unbounded self-directed discovery.
