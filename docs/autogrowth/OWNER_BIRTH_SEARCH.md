## Recovered plan and present question

`CONTEXT_OWNERSHIP_PLAN.md` remains the architecture plan: whole-decision
ownership, experience-driven development, separately specified protection, then
a bounded comparison. Later owner/fivefold/compatibility results revise its next

Does owner-local residual evidence select more useful new conditions than random

## Supplied generic mechanism

Each seed receives a fixed pool of 24 shallow random conditions from the existing
one-to-three-reader AND/OR/exactly-one grammar. A separate seeded RNG generates
the same pool in all four arms, without consuming the original proposal or
exploration streams. This fixed pool is an experimental restriction, not a new
claim of open-ended discovery or reusable hierarchical factoring.

An isolated formal SCRIPT branch observes each candidate on the selected binding
before the real action. Only input terminals read measurements. After the
matching actual scalar outcome, record active/inactive residual counts and sums
in the actual owner. These observers have no scoring edge into action choice.
No alternate action outcome, task/phase label, row identity, fitted weight or
offline capacity result enters nomination. Ancestor evidence is preserved when
an owner splits; children start with no fabricated local observations.

Before a birth, remove exactly-seen definitions and proven contradictions from
the fixed pool. Unknown compatibility remains eligible. Random mode selects
uniformly from all eligible candidates. Residual mode uses the existing split
score n0*n1/(n0+n1)*(mean1-mean0)^2, with four samples on each side; a 25% lottery
selects uniformly from ALL eligible candidates, and so does an absence of a
supported positive score. Unobserved rare and state-only definitions stay
eligible. Both modes consume identical nomination lottery draws per opportunity.
Selected conditions start with zero live weight and receive ordinary credit;
predictive correlation is not maturity or causal usefulness. No pool refill,
semantic deduplication, replacement draws or inherited cleanup is introduced.

Current schedule: a successful split takes the development opportunity; otherwise
one ordinary birth is attempted. Extra-opportunity schedule: after that successful
split, also attempt ONE birth in the child confirmed by the just-completed
action's state-only route observation. No birth is given to an unvisited sibling,
no local visit is invented and the 64-visit clock is unchanged. Subsequent
trajectories/opportunities may diverge, and must be measured. All arms keep the
compatibility gate, ordinary pruning, plasticity and contextual splitting.

## Fixed pilot

Reuse seeds 10/11's verified event-640 source checkpoints. No prefix is retrained.
Each forks into random/current, residual/current, random/extra and residual/extra.
Each receives the previous fivefold continuation: 640 mostly-B then 640 mostly-A
actions, 1,280 per arm. Total 10,240 training actions, 2,560 scheduled evaluation
actions and 2,560 frozen reproduction actions; 160 blocks and 168 new checkpoints.
Evaluate all 16 Boolean development rows every 64 actions on disposable clones.
The earlier compatibility baseline is historical context, not the matched random
null: a fixed candidate pool changes proposal availability even in random mode.

Use one CPU, numerical libraries one thread, 2 GiB address-space limit, 64 MiB
per-file limit, 3,600-second worker deadline and independent 3,630-second timeout
with five-second kill grace. No automatic retry, endpoint extension or tuning on
intermediate results. Preserve incomplete evidence if a limit is reached.

## Verification and measurements

Focused tests cover observer non-interference, actual-outcome binding, local and
ancestor evidence, sibling isolation, random/rare eligibility, zero-weight birth,
both schedules, source immutability and checkpoint continuation. Existing owner,
compatibility and runner tests check the reused paths. No changed chess/core code.

Record immutable submissions/credits, all checkpoints, source snapshots and
completeness manifests. Reproduce scheduled evaluations without further training.
Compare row-level acquisition/loss/recovery, final and worst measured retention,
candidate exposure/ranking/selection, actual birth opportunities and accepted
births, owner visits, parameters, expression definitions and physical nodes
(including the new observer overhead). Record exploration RNG equality; do not
claim matched actions or proposal opportunities after policies diverge.

These prefixes are weak initial policies. This is a development/acquisition
pilot with retention measurements, not the planned strong-skill retention
benchmark. Two reused seeds cannot justify a default change on main. Freeze a
configuration and replicate on fresh seeds before such a promotion proposal.
