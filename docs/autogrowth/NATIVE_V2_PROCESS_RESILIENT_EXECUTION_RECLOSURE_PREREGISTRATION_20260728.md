## Exposure transaction law

Before each unit, an atomic chained `PREPARED` record binds the exact snapshot,
continuation, registry, package map, row order, row definitions and zero
outcome state.

After all 16 probes and the registry scan, an atomic chained `COMMITTED` record
persists commitments, classifier-visible projections, the registry scan
wrapper, target counts, before/after continuation digests, zero-outcome state
and exact record bindings.

Only committed units may be skipped. Every skipped unit is regenerated from
its immutable snapshot and registry and must compare canonically. A dangling
prepared unit may be recomputed because exposure is outcome-blind and
state-preserving; the additional preparation attempt explicitly binds the
abandoned preparation record. Gaps, duplicates, reordering, changed hashes and
foreign records stop.

Partial units never enter aggregation.

After 96 commits, the three registry adjudications, A/B/C row parity, target
opportunities and admission gate are rebuilt exclusively from committed unit
contents. Exposure and execution files are independently deterministic.
Either may be restored after an interruption only if every existing byte
matches the same frozen finalization. A final marker binds both files and the
journal chain.

## Outcome bookkeeping law

Before the outcome environment is constructed, `science_started.json` retires
the complete suffix/cohort/ecology. From that instant it is consumed even if
execution fails.

Failure outcome counts and event identities come only from a validated durable
journal. A valid empty journal means an actual zero. A valid partial journal
reports the exact partial count and events. Invalid journal reconstruction
reports `unknown`; it never defaults to zero.

A caught program failure, a `FAILED` record or a dangling prepared seed is
terminal. Only a clean external interruption with a valid contiguous committed
seed prefix may continue at the next untouched seed after independently
reconstructing all completed seeds.

## Long-lived host law

Future multi-hour commands use a direct user-level systemd transient service:

- literal four-element Python/module argv;
- repository `WorkingDirectory`;
- frozen locale, timezone, Python hash and single-thread environment;
- separate durable stdout/stderr files outside the worktree;
- no shell transformation;
- no wall-clock timeout.

If the user service manager is unavailable, readiness stops and reports the
exact persistent-terminal commands. It must not fall back to an internally
created nohup, setsid or tmux process, nor to another long managed command.
