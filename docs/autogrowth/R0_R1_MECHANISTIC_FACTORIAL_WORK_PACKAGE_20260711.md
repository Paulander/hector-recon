# R0 -> R1 Mechanistic Factorial Work Package

Date: 2026-07-11. Status: development protocol; not preregistered confirmation.

## Question

Can a mature R0 child change R1 parent learning because it recognizes its own
competence and emits learned value, or did the earlier effect primarily come
from exact hypothetical-mate verification, fixed child routing, or hierarchy
scoring?

## Frozen interpretation of prior evidence

The prior 8/16 validation and 5/16 regression result establishes an
oracle-verified upper bound: exact one-ply simulation gated a grounded positive
R0 scalar and changed held-out R1 behavior while hard-frozen R0 was retained.
It does not isolate autonomous availability, value content, routing, or topology.

The later structural smoke is negative development evidence: 0/16 validation,
1/16 regression versus 0/16 and 0/16, four candidates, zero mature, and all
paired interventions neutral. The 1/16 directional difference is not a causal
positive result.

## Development arms

All arms clone one frozen R0; composition is disabled. Child completion is
enabled for every arm during main evaluation so parent learning is comparable.
The identical trained graph is additionally evaluated with child priority off.

1. no bootstrap;
2. learned host gate + learned R0 value;
3. learned host gate + zero value;
4. exactly rate-matched shuffled learned-gate availability + learned value;
5. exact virtual verification + learned value (prior upper bound);
6. exact virtual verification + zero value (call/availability-matched);
7. exact virtual verification + constant placebo value;
8. exact verification + learned value with hierarchy-edge scoring disabled.

The originally listed `real_child_rollout` arm was removed on 2026-07-12 after
external audit showed that it executed the same copied-board terminal probe as
virtual verification and therefore was a semantic duplicate, not a real episode.

## Primary measurements

- parent first-move correctness, calculated laboratory-side only;
- exhaustive all-reply conversion with R0 child completion held constant;
- child reply mate rate;
- availability query/positive counts and rate;
- emitted successor-value sum;
- R0 retention;
- routing on/off delta on the same trained graph;
- query/cache/episode/topology/compute counts;
- immutable checkpoint history and exact resume parity.

## Development decisions

- Learned gate beats its zero-value and shuffled controls: learned availability
  and value carry useful information; next build graph-native availability.
- Exact verification beats learned gate while exact-zero is flat: availability
  recognition is the main missing mechanism.
- Exact learned and exact zero/constant are similar: exact binary availability,
  not learned value content, drove the earlier result.
- Parent correctness rises but conversion falls only with routing off: routing,
  not parent learning, explains the gap.
- All modes remain flat: test successor aggregation before composition.
- Expected-reply learning loses to generic minimum/low-quantile or learned
  counterexample aggregation: objective mismatch was primary.
- Nonlinear offline controls beat linear controls after credit repair: return to
  frozen generic composition release, then KRK no/mined/matched-random growth.

No development outcome advances R2 or sets a causal-positive flag.

## Confirmation boundary

These pools and any repeatedly viewed validation rows are development-only.
After mechanism selection, freeze code and hyperparameters, preregister fresh
disjoint R1 discovery/selection/validation/regression/final pools, run multiple
seeds, use paired-row analysis, and touch regression/final only as declared.
