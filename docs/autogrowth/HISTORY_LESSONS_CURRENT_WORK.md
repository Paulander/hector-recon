# Historical lessons that still govern the current work

Recorded 2026-09-10 at Oskar's request. This is project memory for continuation,
not a new experiment or a revival of historical branch instructions.

## Current user intent

- A reusable ReCoN should explore and adapt in a new environment. The environment
  supplies declared observations, action execution and actual outcome feedback;
  it must not plan graph growth or supply a strategy.
- Learning and developmental control should ultimately belong to the ReCoN's
  internal organization. Generic Python primitives are legitimate, but moving
  an external controller into a node class does not establish graph ownership.
- Prefer explicit hierarchical composition and reusable structures. Separate
  equality terminals (e.g. distance=2/4/6 under OR) are a valid preferred design;
  do not flatten them into a complex SCRIPT merely to reduce node count.
  Their underlying stable measurement may be shared without merging terminal
  request states or leaking bindings/frames. Better learning is a hypothesis.
- Independently trained children are permitted. The missing autonomy is learned
  contextual delegation, not whether the children began as separate objects.

## What is fixed, and what remains open

The current adapter exposes file/rank distances separately; the historical
closest-edge precedence suppression was not reproduced in the current symmetry
checks. The current policy chooses through the formal graph and updates the
selected prediction. Preserve these repairs rather than assuming every old bug
is still active.

Reliable retention, reusable hierarchical growth, learned child availability,
internal developmental control and general M2 competence remain open. More
training has helped several current M1 histories, so a short plateau alone is
not evidence for a new mechanism. The interrupted learning-rate comparison
provides no completed rate result.

The immediate architectural discussion is about internal adaptation boundaries,
native sequencing and nested reuse while preserving explicit leaf terminals.
It has not implemented those changes. POR/RET integration must respect the
existing distinction between TRUE and CONFIRMED and sequence completion; simply
adding sequence edges to the current CONFIRMED-only actuator guard is insufficient.
Higher-level reuse must preserve single-parent SCRIPT execution instances, with
separate bindings and frame state. Exact factoring and measurement caching are
different interventions from changing learned routing or reward credit.
