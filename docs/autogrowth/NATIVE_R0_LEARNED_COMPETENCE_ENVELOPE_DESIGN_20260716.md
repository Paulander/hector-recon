# Graph-Native Learned R0 Competence Envelope Design

Date: 2026-07-16. Status: design/preregistration draft only. Do not implement,
train, or open fresh data without a separate authorization and freeze.

## Objective

Learn a graph-native AVAILABLE signal that predicts whether the mature R0 policy,
when formally requested in the current local context, will complete its own
declared goal with its own selected action. This is an abstention/competence
envelope around the existing policy, not a second move selector.

The diagnostic prerequisite passed: perfect policy-success availability selected
`d8c8` and converted the retired R1 row; shuffled and disconnected controls did
not. Any-response availability failed.

## Constitutional contract

- POLICY_RESPONSE: a child action was formally emitted. It may be used for
  exploration but never implies applicability.
- AVAILABLE: a graph-local outcome-calibrated prediction that this requested
  child script completes now. Only AVAILABLE may feed exploitative all-reply
  handover.
- VALUE: expected return conditional on AVAILABLE.
- GROUNDING: acyclic provenance from earlier real outcomes; it never means the
  child applies to the present state.
- ACTION_OPTION remains `AND(legal actuator, ALL_REPLIES_AVAILABLE)`.
- Zero exploit options yields zero exploit actuators. A separate anonymous graph
  exploration SCRIPT may act, with no host fallback.

## Learner-visible evidence

Candidate-local evidence may include only ordinary graph state already recorded
in the diagnostic artifact:

- active atom identities and activations;
- active mature composite identities;
- selected policy-response strength and margin represented inside the graph;
- local request, confirmation, negative-confirmation, and false-positive history;
- local real completion successes/failures;
- maturity, grounding provenance, and child-owned uncertainty.

It may not include FEN identity, curriculum/stage labels, mate distance, correct
moves, forced-mate predicates, any-action-success, tablebases, Stockfish, the
retired R1 row identity, or the old host prototype probability.

## Proposed topology

For each mature child policy branch, materialize candidate-local internal
terminals for POLICY_RESPONSE and real completion history. A generic competence
SCRIPT composes those terminals with selected active atoms/composites and emits
AVAILABLE. The measurement backend may read graph-owned counters, but Python may
not reconstruct availability or select thresholds at runtime. The AVAILABLE
SCRIPT must serialize with the organism and execute through FormalReConEngine.

Availability learning occurs only after this real sequence:

`request child -> child emits action -> execute action in reality -> environment
reports terminal fact -> declared completion terminal confirms/fails -> update
local competence evidence`.

A noncompletion is a local negative competence example. Unless the environment
separately reports stalemate, rook loss, or another terminal failure, it is not a
chess loss and supplies no fabricated terminal reward. Dreams never update the
envelope or certify themselves.

## Frozen development split proposal

Do not tune on the single retired R1 row. If implementation is separately
authorized, use only the already-touched historical split for development:

- fit/grow on existing R0 train outcomes plus gate-train decoys;
- select structure/threshold through graph dynamics on existing R0 validation
  plus gate-validation decoys;
- freeze and touch existing R0 regression plus gate-regression decoys once;
- use the 65 retired successors only as a final development diagnostic, not as a
  training or threshold-selection set.

The old prototype gate remains a disconnected laboratory upper bound. The
any-action-success mask remains diagnostic only.

## Arms

1. Graph-native learned competence envelope.
2. Identical envelope output disconnected from parent.
3. Availability identities shuffled with multiset and row parity.
4. Current any-policy-response contract as a known nonselective reference.
5. Old prototype gate as laboratory-only upper bound, never a runtime arm.

Exploration schedule, R0 graph, retrieval budget 16, R0 weights, child VALUE,
all-reply topology, opponent transition order, and parent choice genome remain
fixed. No R1 learning is mixed into this competence experiment.

## Predeclared development gates

- 32/32 retained R0 policy completion remains exact.
- Zero AVAILABLE false positives on the 48 existing touched decoys.
- Every unavailable reply formally eliminates its parent action option.
- No qualified option emits zero exploit actuators; graph exploration is separate.
- On the retired 65 successors, learned availability is directionally closer to
  policy success than any-response availability; report all 65 rows.
- On the retired R1 row, the learned arm selects `d8c8` and converts while
  shuffled/disconnected do not. This remains development evidence only.
- Zero host fallback, old-selector runtime calls, dream mutation, dream credit,
  topology leakage, and R0 regression.
- Serialization/inference parity is exact.

Do not lower these gates after observing results.

## Kill rules

- If graph-native AVAILABLE cannot separate touched retained R0 from touched
  decoys without using forbidden features, close this representation.
- If it separates those pools but not the 65 retired successors, investigate
  local representation/coverage as a new isolated factor; do not add host gates.
- If it predicts policy success but parent behavior does not change, stop at
  all-reply/choice integration.
- If behavior changes but retained R0 drifts, stop at consolidation/stability.
- Spawning and credit remain untested until learned R1 topology is explicitly
  connected to evaluation in a later package.

## Fresh confirmation and transfer

No fresh run is authorized by this document. After a successful touched-data
development package, an external freeze must define unused multi-seed contexts,
separate train/validation/final pools, calibration statistics, and one-touch
final handling. Only that future package could support an autonomous competence
claim or authorize native R1 learning.
